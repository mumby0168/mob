AI mob programming. Each engineer gets Claude Code as their driver. A shared context layer in git keeps both agents in sync. No extra tools. Just a branch and a folder.

Right now you can pair program with AI. One human, one agent. It works. But when two engineers collaborate, the agents are blind to each other. Context gets lost at every handoff. You re-explain. You duplicate work. You step on each other's code.

How it works
01

Branch triggers the mode

Check out mobbing/auth-refactor. Claude detects the branch prefix and enters mob mode automatically. It sets up a .mob/ directory and walks you through defining the session goal and plan.

02

Work with your agent

Claude drives, you navigate. Normal AI pair programming. But now Claude commits frequently, pushes immediately, and writes a context update to .mob/ with every commit — what it did, what's next, what to watch out for.

03

Context stays in sync

Claude pulls every 2 turns and reads the other engineer's context file and turn log. It knows what the other pair is working on, what decisions they made, and what they tried. No re-explaining.

04

Take turns or work in parallel

Hand off by pushing and telling the other person to pull. Or work simultaneously on different parts — Claude reads the other pair's focus area and stays out of their files.

05

Decisions propagate instantly

Say "let's change the approach to use queues instead." Claude updates the session context and commits it separately. The other engineer's Claude picks up the decision on next pull — before any code follows from it.

What lives in .mob/
.mob/auth-refactor/
session.md # goal, plan, scope, shared decisions
log.md # append-only turn log — who asked what, what happened
alice.md # Alice's context — focus, last commit, notes for Bob
bob.md # Bob's context — focus, last commit, notes for Alice

Plain markdown. Versioned in git. No external services. Each Claude reads the full .mob/ directory on every pull and updates its own files on every commit. The turn log captures sanitised prompt summaries and actions so the other agent can follow the reasoning, not just the code.

The commit loop
while mobbing:
  git pull --rebase            # every 2 turns
  read .mob/*.md               # pick up other pair's context
  work()                       # claude drives, you navigate
  update .mob/you.md           # write context + append to log
  git add -A && commit && push # one action, always together
